## Executive Summary

This document defines the Firestore database schema and data architecture for the BabyTrack platform. The design prioritizes scalability, modularity, and real-time sync capabilities.

---

## Design Principles

| Principle | Implementation |
|-----------|----------------|
| **Scalability** | Subcollections for unbounded data (photos, logs) |
| **Performance** | Embedded documents for frequently-read data (latestVitals) |
| **Flexibility** | Cross-references via IDs, not embedded documents |
| **Evolution** | All documents have `version` field for migrations |
| **Safety** | Soft deletes with `deletedAt` timestamps |

## Data Access Patterns

### Read-Heavy Paths (Optimized)

| Path | Pattern | Optimization |
|------|---------|--------------|
| Dashboard vitals | Single baby doc read | Embedded `latestVitals` |
| Photo timeline | Baby photos subcollection | Pagination + thumbnail URLs |
| Family members | Family members subcollection | Denormalized names |
| Active tips | Tips query by age | Composite index on age range |

### Write-Heavy Paths

| Path | Pattern | Strategy |
|------|---------|----------|
| Vitals updates | Every 5-10 seconds | Batch writes, rate limiting |
| Sleep sessions | Start/end events | Cloud Function aggregation |
| Photo uploads | User initiated | Async AI processing |

### Common Queries

```typescript
// Get baby's recent photos
db.collection('babies').doc(babyId)
  .collection('photos')
  .where('isArchived', '==', false)
  .orderBy('capturedAt', 'desc')
  .limit(20);

// Get tips for baby's age
const ageMonths = calculateAge(baby.dateOfBirth);
db.collection('tips')
  .where('targeting.ageMinMonths', '<=', ageMonths)
  .where('targeting.ageMaxMonths', '>=', ageMonths)
  .where('isPremium', '==', false);

// Get family members with access
db.collection('families').doc(familyId)
  .collection('members')
  .where('status', '==', 'active');

// Get today's sleep sessions
const startOfDay = new Date(); startOfDay.setHours(0,0,0,0);
db.collection('babies').doc(babyId)
  .collection('sleepSessions')
  .where('startTime', '>=', startOfDay)
  .orderBy('startTime', 'asc');
```

## Security Rules Summary

```javascript
// Simplified security rules structure
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    
    // Users can only read/write their own document
    match /users/{userId} {
      allow read, write: if request.auth.uid == userId;
    }
    
    // Family access based on membership
    match /families/{familyId} {
      allow read: if isFamilyMember(familyId);
      allow write: if isFamilyOwner(familyId);
      
      match /members/{memberId} {
        allow read: if isFamilyMember(familyId);
        allow write: if isFamilyAdmin(familyId);
      }
    }
    
    // Baby access based on family membership
    match /babies/{babyId} {
      allow read: if canAccessBaby(babyId);
      allow write: if canEditBaby(babyId);
      
      match /photos/{photoId} {
        allow read: if canAccessBaby(babyId);
        allow create: if canEditBaby(babyId);
        allow update, delete: if isPhotoOwner(photoId);
      }
    }
    
    // Devices require ownership or family access
    match /devices/{deviceId} {
      allow read: if canAccessDevice(deviceId);
      allow write: if isDeviceOwner(deviceId);
    }
    
    // Tips are globally readable
    match /tips/{tipId} {
      allow read: if true;
      allow write: if false; // Admin only
    }
  }
}
```

## 🔄 Device-to-App Connection Flow

### How App and Device Know Each Other

The connection between ESP32 devices and the Flutter app works through **shared document IDs** in Firestore:

#### **Step 1: Device Registration**
```
ESP32 Device → Cloud Function/API
POST /api/devices/register
{
  "deviceSerialNumber": "ESP32-ABC123",
  "macAddress": "AA:BB:CC:DD:EE:FF",
  "firmwareVersion": "1.0.0",
  "familyId": "fam_xyz123"  // From WiFi provisioning
}

Response:
{
  "deviceId": "dev_xyz789",
  "authToken": "secret_token_123"
}
```

**What happens:**
- Cloud Function creates document in `devices/{deviceId}` collection
- Sets `familyId` to link device to the family that set it up
- Returns `deviceId` for device to store in flash memory

#### **Step 2: App Discovery**
```dart
// App queries for family's devices
final devices = await firestore
  .collection('devices')
  .where('familyId', isEqualTo: userFamilyId)
  .get();
```

**App now knows:**
- All devices belonging to this family
- Device status (online/offline)
- Which baby each device is monitoring

#### **Step 3: Baby Assignment**
```dart
// User assigns device to baby via UI
await firestore.collection('devices').doc(deviceId).update({
  'assignedBabyId': babyId
});
```

**Connection established:**
- Device document now links: `familyId` → `assignedBabyId`
- ESP32 knows its `deviceId`
- App knows which device monitors which baby

#### **Step 4: Real-Time Data Flow**

**ESP32 sends vitals:**
```cpp
// Device writes to Firestore every 5-10 seconds
POST /v1/projects/{projectId}/databases/(default)/documents/vital_signs
{
  "deviceId": "dev_xyz789",      // I am this device
  "babyId": "baby_abc123",       // Monitoring this baby
  "heartRate": 120,
  "bodyTemperature": 36.8,
  "timestamp": "2026-02-04T10:30:00Z"
}
```

**App receives vitals:**
```dart
// Real-time listener for baby's vital signs
firestore
  .collection('vital_signs')
  .where('babyId', isEqualTo: selectedBabyId)
  .orderBy('timestamp', descending: true)
  .limit(10)
  .snapshots()  // 🔥 Real-time updates
  .listen((snapshot) {
    // UI updates instantly when device sends new data
  });
```

### Key Connection Points

| Entity | Knows About | Via Field |
|--------|-------------|-----------|
| **User** → Family | `users/{userId}.familyId` |
| **Family** → Devices | `devices` query `where familyId == family.id` |
| **Device** → Baby | `devices/{deviceId}.assignedBabyId` |
| **App** → Vitals | `vital_signs` query `where babyId == baby.id` |
| **ESP32** → Identity | Stores `deviceId` in flash memory |

### What to Check in Firebase Console

After device connects, verify these collections:

**1. Check `devices/{deviceId}`:**
```
✅ status: "online"
✅ lastSeenAt: recent timestamp (< 1 min ago)
✅ familyId: matches user's family
✅ assignedBabyId: set to correct baby
✅ wifiInfo.rssi: signal strength value
```

**2. Check `vital_signs` collection:**
```
Query: babyId == {your_baby_id}
✅ New documents every 5-10 seconds
✅ Each has deviceId + babyId fields
✅ heartRate, respiratoryRate, bodyTemperature present
```

**3. Required Indexes:**
```
vital_signs:
  - babyId (ASC) + timestamp (DESC)
  - deviceId (ASC) + timestamp (DESC)
```

### Typical Flow Summary

```
1. Parent signs up → creates user + family
2. Parent adds baby → creates baby with familyId
3. Parent clicks "Add Device"
4. WiFi provisioning connects ESP32 to WiFi + Cloud
5. ESP32 registers → creates device with familyId
6. Parent assigns device to baby → sets assignedBabyId
7. ESP32 sends vitals with deviceId + babyId
8. App listens where babyId == baby.id
9. Real-time dashboard updates ✨
```

**No direct device ↔ app communication!** Firebase Firestore is the intermediary.
