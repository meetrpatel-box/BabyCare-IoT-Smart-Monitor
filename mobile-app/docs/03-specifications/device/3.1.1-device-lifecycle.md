## Executive Summary

This document specifies the complete lifecycle of the AnvayaPod IoT device, from unboxing to continuous monitoring. It covers all device states, transitions, failure scenarios, and recovery procedures.

## LED Status Indicators

| LED Pattern | State | Meaning |
|-------------|-------|---------|
| **Off** | Unpowered | Device not receiving power |
| **Slow Blue Pulse** (1s) | Pairing | Ready for BLE connection |
| **Fast Blue Blink** (0.5s) | Provisioning | Receiving WiFi credentials |
| **Purple Pulse** | Connecting | Connecting to cloud services |
| **Solid Green** | Registered | Setup complete |
| **Green Breathing** | Online | Normal operation, streaming data |
| **Yellow Pulse** | Recovering | Attempting to reconnect |
| **Red Solid** | Offline/Error | Needs user attention |
| **Red Blink** | Critical Error | Hardware or sensor failure |

### Normal Flow

```
UNBOXED → PAIRING → PROVISIONING → CONNECTING → REGISTERED → ONLINE
   │         │           │             │            │           │

```

### Recovery Flow

```
ONLINE ──► WIFI_DISCONNECTED ──► RECOVERING ──► ONLINE
              │                        │
              │                        │ Failed after 30 min
              │                        ▼
              │                    OFFLINE
              │                        │
              └────────────────────────┘
                   User intervention required
```

## Failure Scenarios

### 1. Pairing Failures

| Failure | Cause | User Message | Recovery |
|---------|-------|--------------|----------|
| `BLE_UNAVAILABLE` | Phone BT off/unsupported | "Bluetooth is required" | Open BT settings |
| `DEVICE_NOT_FOUND` | Pod not in pairing mode | "No pod found nearby" | Reset pod to pairing |
| `BLE_CONNECTION_FAILED` | Interference, distance | "Connection failed" | Move closer, retry |
| `PAIRING_TIMEOUT` | No activity for 5min | Auto-restart pairing | Press pod button |

### 2. WiFi Provisioning Failures

| Failure | Cause | User Message | Recovery |
|---------|-------|--------------|----------|
| `WIFI_NOT_FOUND` | SSID not visible | "Network not found" | Check 2.4GHz, move closer |
| `WIFI_AUTH_FAILED` | Wrong password | "Password incorrect" | Re-enter password |
| `WIFI_5GHZ_ONLY` | Router 5GHz only | "2.4GHz required" | Enable 2.4GHz band |
| `WIFI_TIMEOUT` | Slow connection | "Connection timed out" | Retry |
| `DHCP_FAILED` | No IP assigned | "Network configuration failed" | Restart router |

### 3. Cloud Connection Failures

| Failure | Cause | User Message | Recovery |
|---------|-------|--------------|----------|
| `CLOUD_DNS_FAILED` | DNS not working | "Internet issue detected" | Check router internet |
| `CLOUD_AUTH_FAILED` | Invalid device cert | "Registration failed" | Contact support |
| `CLOUD_TIMEOUT` | Slow internet | "Connection timed out" | Retry |
| `CLOUD_FIREWALL` | Port blocked | "Firewall blocking" | Check router settings |

### 4. Runtime Failures

| Failure | Cause | User Message | Recovery |
|---------|-------|--------------|----------|
| `WIFI_DISCONNECTED` | Router reboot, range | "WiFi lost, reconnecting..." | Auto-retry |
| `CLOUD_DISCONNECTED` | Internet outage | "Cloud connection lost" | Auto-retry |
| `SENSOR_ERROR` | Hardware malfunction | "Sensor issue detected" | Restart pod |
| `FIRMWARE_CRASH` | Software bug | "Pod restarted unexpectedly" | Check for update |

## Recovery Procedures

### Auto-Recovery (No User Action)

```typescript
const AUTO_RECOVERY_CONFIG = {
  wifi_reconnect: {
    immediate_retries: 3,
    retry_interval: '5s',
    backoff_multiplier: 2,
    max_interval: '5min',
    max_duration: '30min',
    fallback: 'OFFLINE_STATE'
  },
  cloud_reconnect: {
    immediate_retries: 5,
    retry_interval: '10s',
    backoff_multiplier: 1.5,
    max_interval: '2min',
    max_duration: '30min',
    fallback: 'OFFLINE_STATE'
  },
  sensor_recovery: {
    i2c_reset_attempts: 3,
    sensor_power_cycle: true,
    fallback: 'SENSOR_DEGRADED'
  }
};
```

### User-Initiated Recovery

| Problem | User Action | Expected Result |
|---------|-------------|-----------------|
| Pod stuck | Power cycle (unplug 10s) | Pod restarts, resumes |
| Won't pair | Hold button 10s (factory reset) | Enters pairing mode |
| Wrong WiFi | In-app "Change WiFi" | Re-provision network |
| Persistent offline | In-app troubleshoot wizard | Guided diagnosis |

### Factory Reset

```
To factory reset the AnvayaPod:
1. Ensure pod is powered on
2. Press and hold the button for 10 seconds
3. LED will blink red 3 times
4. LED will turn off briefly
5. LED will begin slow blue pulse (pairing mode)
6. All settings are erased
7. Device must be re-provisioned
```

## Troubleshooting Wizard

The app includes a guided troubleshooting flow:

```
Step 1: What's the LED color?
├── Blue pulsing → Device in pairing mode
├── Green → Device online (app issue)
├── Yellow → Device recovering
├── Red → Device error
└── Off → Device unpowered

Step 2: (Based on Step 1)
├── Check power connection
├── Check WiFi router
├── Check internet connection
├── Try power cycle
└── Contact support

Step 3: Verify fix
├── Device back online → Success
└── Still offline → Escalate to support
```
