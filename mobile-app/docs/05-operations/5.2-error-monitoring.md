## Executive Summary

This document defines the error monitoring, collection, and alerting system for the AnvayaPod platform. It covers error taxonomy, collection architecture, alerting strategy, and dashboards for operations.

---

## Error Code System

### Format

```
Error Code Format: [CATEGORY]-[COMPONENT]-[SEVERITY][CODE]

Example: SNS-SPO2-C001 = Critical SpO2 sensor failure #001
```

### Categories

| Code | Category | Description |
|------|----------|-------------|
| `BLE` | Bluetooth | BLE pairing and communication |
| `WIFI` | WiFi/Network | WiFi connection and networking |
| `CLD` | Cloud | Firebase and cloud connectivity |
| `SNS` | Sensors | Hardware sensors (SpO2, temp, etc.) |
| `PWR` | Power | Battery and power management |
| `FW` | Firmware | Device firmware and system |
| `APP` | Mobile App | Flutter app errors |
| `SEC` | Security | Authentication and authorization |

### Severity Levels

| Code | Level | Description | Response Time |
|------|-------|-------------|---------------|
| `C` | Critical | Immediate user safety risk | < 1 minute |
| `E` | Error | Functionality broken | < 15 minutes |
| `W` | Warning | Degraded but functional | < 1 hour |
| `I` | Info | Logged for analysis | Next business day |

## Error Report Schema

```typescript
interface ErrorReport {
  id: string;
  deviceId?: string;
  userId?: string;
  babyId?: string;
  
  error: {
    code: string;                // "SNS-SPO2-E001"
    category: string;
    component: string;
    severity: 'critical' | 'error' | 'warning' | 'info';
    message: string;
    technicalMessage?: string;
  };
  
  context: {
    timestamp: Timestamp;
    firmwareVersion?: string;
    appVersion?: string;
    osVersion?: string;
    
    system?: {
      freeHeapBytes: number;
      cpuTemperatureC: number;
      uptimeSeconds: number;
    };
    
    connectivity?: {
      wifiRssi: number;
      cloudConnected: boolean;
    };
    
    sensors?: {
      spo2Value?: number;
      spo2Quality?: number;
    };
  };
  
  recovery: {
    attempted: boolean;
    action?: string;
    successful?: boolean;
  };
  
  metadata: {
    reportedAt: Timestamp;
    schemaVersion: number;
  };
}
```

## Alerting Strategy

### Alert Routing Matrix

| Error Type | Parent | Support | Eng | On-Call | Response |
|------------|--------|---------|-----|---------|----------|
| SpO2 Critical | ✅ | - | - | - | Immediate push |
| Device Offline >5min | ✅ | - | - | - | Immediate push |
| Error Spike (>3x) | - | ✅ | ✅ | - | Slack + investigate |
| Regional Outage | - | ✅ | ✅ | ✅ | PagerDuty |
| FW Regression | - | - | ✅ | ✅ | Slack + evaluate |

## Anomaly Detection Rules

### Error Spike Detection

```sql
-- Alert when error rate exceeds 3x normal
SELECT 
  error_code,
  COUNT(*) as current_count,
  AVG(baseline_count) as baseline
FROM errors
WHERE timestamp >= NOW() - INTERVAL 15 MINUTE
GROUP BY error_code
HAVING current_count > baseline * 3
```

### Firmware Regression Detection

```sql
-- Compare error rates between firmware versions
WITH version_rates AS (
  SELECT 
    firmware_version,
    error_code,
    COUNT(*) / COUNT(DISTINCT device_id) as error_rate
  FROM errors
  WHERE timestamp >= NOW() - INTERVAL 7 DAY
  GROUP BY firmware_version, error_code
)
SELECT * FROM version_rates
WHERE firmware_version = @new_version
  AND error_rate > (
    SELECT error_rate FROM version_rates 
    WHERE firmware_version = @old_version
  ) * 1.5
```

### Hardware Batch Detection

```sql
-- Identify manufacturing batch issues
SELECT 
  SUBSTR(device_serial, 1, 6) as batch,
  COUNT(DISTINCT device_id) as affected_devices,
  COUNT(*) / COUNT(DISTINCT device_id) as errors_per_device
FROM errors
WHERE error_code LIKE 'SNS-%'
GROUP BY batch
HAVING affected_devices > 50 AND errors_per_device > 5
```
